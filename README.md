# Enkinex Ossie — Apache Ossie as Code Library

[![Standard](https://img.shields.io/badge/Ossie-0.2.0.dev0-blue)](https://github.com/apache/ossie)
[![KCL](https://img.shields.io/badge/KCL-%E2%89%A5%200.12.8-7B68EE)](https://www.kcl-lang.io/)
[![Version](https://img.shields.io/badge/version-0.2.0.dev0-orange)](./CHANGELOG.md)
[![License](https://img.shields.io/badge/license-Apache--2.0-green)](./LICENSE)

> A modular [KCL](https://www.kcl-lang.io/) library for the
> [Apache Ossie Core Metadata Specification 0.2.0.dev0](https://github.com/apache/ossie),
> built to author, type-check, and validate Apache Ossie semantic model definitions.

## Schema Library Modules

The standard's `core-spec/osi-schema.json` organizes its definitions by
concern; this library keeps that grouping as one KCL module per section:

| Module                | Purpose                                                                                            | Detailed docs                                   |
|------------------------|-----------------------------------------------------------------------------------------------------|--------------------------------------------------|
| **`common`**           | Cross-cutting building blocks: `Dialect`/`DataType`/`Vendor` enums, multi-dialect `Expression`, `AIContext`, `CustomExtension`. | [docs/schemas/common](docs/schemas/common.md)   |
| **`catalog`**          | The dataset shape: logical datasets, their fields (with dimension metadata), and foreign-key relationships. | [docs/schemas/catalog](docs/schemas/catalog.md) |
| **`metric`**           | Quantitative measures defined at the semantic-model level, potentially spanning multiple datasets.  | [docs/schemas/metric](docs/schemas/metric.md)   |
| **`model`**            | The `SemanticModel` container that references datasets, relationships, and metrics.                 | [docs/schemas/model](docs/schemas/model.md)     |
| **`ossie.k`** *(root)* | The root **`OssieDocument`** schema. It imports from every module and composes the final document.  | [docs/schemas/ossie](docs/schemas/ossie.md)     |

## Schema Library Reference

The complete, per-schema API reference is **auto-generated by the KCL CLI**
from the schema docstrings and property definitions:

**➡ [Enkinex Ossie Schemas Reference](docs/library/ossie.md)**

Regenerate it after any schema change with `just docs`.

## Schema Library Commands

Common tasks are wrapped in the [`Justfile`](Justfile):

```bash
just init      # sync library module dependencies
just test      # kcl vet the fixtures under test/ against the schemas
just docs      # regenerate docs/library/ossie.md from the schema docstrings
just check     # fmt + clean-tree + lint + test — the gate every change must pass
```
